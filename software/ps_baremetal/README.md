# Zybo OPNA PS baremetal

From the repository root, `py -3 -X utf8 scripts/build_phase7_ps.py --xsa <existing-XSA>` generates a fresh Cortex-A9 standalone BSP, compiles the application with the installed Vitis 2025.2 SDK, links the SDK startup/cache/interrupt drivers, and runs execution tests using the Vivado 2025.2 bundled MinGW compiler. `XILINX_VITIS` and `OPNA_VIVADO_ROOT` select the existing installations. Output is `build/opna_phase7/board/software/result.json` and `opna_ps.elf`; `board_verified` remains false. The local Counterattack fixture must first be prepared using `scripts/prepare_reference_assets.py`.

The complete board including both ILAs uses 11,576 LUT and 12,343 FF. Routed WNS is +0.262 ns, TNS is zero and WHS is +0.051 ns. The matched XSA, bitstream and normal bulk firmware passed digital board acceptance; see [Phase 7](../../docs/phases/phase-07.md). For Windows class-compliant MIDI playback use [USB MIDI firmware](../usb_midi/README.md).

The USB framing, bulk endpoint handlers, 8 MiB event buffer, and timer/codec routines derive from [ryujou/zybo-opl3-fpga](https://github.com/ryujou/zybo-opl3-fpga/tree/49b6efe07d79cb74856c7e70398dfcc612b101cf/software/src), itself based on [gtaylormb/opl3_fpga](https://github.com/gtaylormb/opl3_fpga). The extracted source files are `opl_stream`, `transport`, `transport_backend`, `transport_usb`, `transport_uart`, `usb_ch9`, `usb_descriptors`, `ssm2603`, `timer_ps`, and `lscript.ld`. The OPNA adaptation uses four native byte ports, actual IC reset, RUN pause, complete native sample DDR, and 16-bit codec playback. The source project's LGPLv3 license is retained in `LICENSES/LGPL-3.0.txt` with its required GPLv3 text. The timer source retains Sam Bobrowicz / Copyright 2014 Digilent Inc. notices; `lscript.ld` retains AMD's 2023 MIT notice and the text in `LICENSES/MIT.txt`. Commercial SDK sources and libraries are generated locally by Vitis and are not included here.

USB uses vendor interface `CAFE:4012`, EP1 bulk OUT/IN, 64-byte packets, and the existing WinUSB compatibility descriptor. PS GPIO MIO46 resets the Zybo USB PHY. The firmware configures PS I2C0 at 100 kHz and codec address `0x1A`: software reset, power with OUT disabled, DAC path and volume, slave 16-bit I2S (`R7=2`), normal 48 kHz at nominal 12.288 MHz (`R8=0`), 75 ms VMID charge, ACTIVE (`R9=1`), then OUT enabled. The sequence and bit assignments follow [SSM2603 Rev. D, pp. 11, 17, 24–27](https://www.analog.com/media/en/technical-documentation/data-sheets/ssm2603.pdf). USB enumeration and I2S have been verified on the board; analog output has not been measured.

GP0 MMIO starts at `0x43C00000`. Each register transaction writes its bank's address byte then data byte at offsets `0/1` or `2/3`; each byte checks native busy, reset, and host-pending status. AXI responses follow actual WR release, and hardware enforces native and rhythm recovery. IC is requested through CONTROL, rather than by writing zero to chip registers. Pause clears RUN and mutes; resume preserves oscillator/envelope/memory state. A DDR error prevents native writes until actual IC reset.

The global timer and SCU delay use the fresh BSP's `COUNTS_PER_SECOND`, with one count per two CPU cycles and no additional correction factor. Uploaded delays are unsigned microseconds relative to the previous event; each event contains a count and `bank,register,value` triples. Playback cumulatively adds these delays to one absolute start time. A separate chip-bus cursor expands writes to `max(source_due,cursor)`, with conservative 32 µs ordinary and 78 µs rhythm-key transactions, matching Phase 6's 512/1248 half ticks at 16 MHz. Hardware busy waits still apply. Dispatch lateness measures actual processing start after this expanded deadline; it does not treat legal serialization as a lost write. Host tests separately report completion time relative to the unexpanded source deadline. Pause shifts the entire source timeline and chip cursor by the same timer interval.

The application linker bounds every allocated section, including the 8 MiB event buffer, below `0x01000000`. Native sample DDR begins at `0x01000000`, reserving 512 KiB physically with 256 KiB of addressable payload. ROM/RAM8 use 18-bit byte addresses. RAM1's eight banks share the same packed payload: `byte = bank*32768+(address>>3)`, `bit = address&7`. CPU upload stops RUN, waits for DDR idle, initializes the full native payload to zero, copies bytes, flushes all 256 KiB, then resumes RUN to invalidate the PL cache. CPU readback stops RUN and invalidates this cache range before copying; it leaves RUN paused until resume/reset.

Protocol 2.1 retains `4F 50 type length_le16 payload checksum8`, where the required frame checksum is the low byte of the sum of type, both length bytes, and payload. Original commands `01..0D` keep their framing: HELLO, enter, live event, stop, IC reset, status, exit, event upload begin/chunk/end, buffered play/pause/resume. Event upload begin contains its total byte count as `u32le`; chunk bytes concatenate consecutively. Each buffered event is `delay_us:u32le,count:u8,(bank:u8,register:u8,value:u8)*count`. Invalid banks, malformed records, over-capacity uploads, incomplete uploads, and USB transport errors are reported.

| Type | Sample command payload |
| --- | --- |
| `0E` | Begin: `offset:u32le,size:u32le,memory_type:u8` (`0=ROM,1=RAM8,2=RAM1`), complete range within 256 KiB |
| `0F` | Consecutive raw sample bytes, up to negotiated frame capacity |
| `10` | End: empty; loaded byte count must exactly match begin |
| `11` | Read: `offset:u32le,length:u16le`, reply is the requested raw bytes; disallowed during unpaused playback or upload |

Responses use `type|80`; errors use `7F` and one error-code byte. HELLO keeps its 24-byte capability payload, with version `2,1`. STATUS retains its original first five bytes (`free_slots:u16le,queued_writes:u16le,flags:u8`, flag bit0 playing and bit1 paused), followed by `hardware_status:u32le,dispatch_late_writes:u32le,max_dispatch_lateness_us:u32le,sample_loaded:u32le`. These are local control and diagnostic fields, not a claim of measured board timing.

The host contract executes the actual source parser, MMIO calls, USB endpoint callbacks/descriptors, upload/play/pause code, codec sequence, timer conversion, and sample cache handoff with mocked BSP I/O. Its real input is the frozen Counterattack VGM first second: all 887 bank/register/value writes and all 34,560 sample bytes compare exactly after host framing. Additional checks cover the exact 8 MiB event limit, the last RAM1 bank/address, USB failure/reset/overflow, native busy/IC/fault, and all codec failures. Offline compilation and mocked execution do not prove electrical behavior, actual USB enumeration, audio quality, or board timing.
